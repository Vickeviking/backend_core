# ADRs

This directory is reserved for Architecture Decision Records.

An ADR should be added when the team makes a decision that changes the long-term shape of the system, for example:

- whether to stay on Actix or migrate to Axum
- whether to add a separate frontend
- whether to introduce background workers
- whether to split the project into multiple crates
- how authentication and authorization should work

Each ADR should be short, dated, and explicit about:

- the context
- the decision
- the tradeoffs
- the consequences

The goal is not to create ceremony. The goal is to preserve reasoning that would otherwise be lost.
